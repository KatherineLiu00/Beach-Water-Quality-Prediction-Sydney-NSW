# Beach Water Quality Prediction (Sydney, NSW)

Machine learning pipeline for predicting recreational beach water quality in Greater Sydney, NSW. The project combines official [NSW Beachwatch](https://www.beachwatch.nsw.gov.au/waterMonitoring/waterQualityData) monitoring records with daily weather data to classify water quality as **Good**, **Fair**, or **Poor**.

**Author:** Katherine Liu

---

## Overview

Beach water quality affects public health, beach operations, and community confidence. This repository provides a reproducible end-to-end workflow:

- Data integration from water-quality and weather sources
- Exploratory data analysis (EDA)
- Feature engineering and preprocessing
- Training and hyperparameter tuning of five classification models
- Performance evaluation with confusion matrices, Macro-F1, ROC-AUC, and PR-AUC

The main deliverable is an R Markdown report that documents the full analysis and can be rendered to HTML.

---

## Features

- **Multiclass classification** of beach status (Good / Fair / Poor) based on NSW enterococci guidelines
- **Five models** compared: Multinomial Logistic Regression, LDA, RBF-SVM, KNN, and Naive Bayes
- **Imbalanced-data handling** via downsampling on the training set only
- **10-fold cross-validation** with parallel training via `caret`
- **Engineered features** including log transforms, Yeo-Johnson precipitation, interaction terms, and seasonal indicators

## Water Quality Classes

Labels are derived from *Enterococci* counts (`enterococci_cfu_100ml`) following NSW recreational water guidelines:

| Class | Threshold (CFU/100 mL) |
|-------|------------------------|
| **Good** | ≤ 200 |
| **Fair** | 201 – 500 |
| **Poor** | > 500 |

## Methodology

```
Load raw data
    ↓
Left-join on date
    ↓
Exploratory Data Analysis
    ↓
Feature Engineering
    ├── Drop redundant weather coordinates
    ├── Filter missing / negative values
    ├── Median imputation (water temp, conductivity)
    ├── Outlier capping (1st–99th percentile)
    ├── Z-score standardization
    ├── Build class labels
    └── Log / Yeo-Johnson transforms, interactions, season
    ↓
Train/test split (80 / 20)
    ↓
Downsample training set
    ↓
Train 5 models with 10-fold CV + hyperparameter tuning
    ↓
Evaluate on imbalanced hold-out test set
```

### Modeling Features

Five predictors are used for classification:

- `log_enterococci`
- `yeojohnson_precip`
- `temp_ec_interact`
- `temp_diff`
- `season`

### Models

All models are trained with **`caret`**, using **10-fold cross-validation** and **downsampling** on the training set. The test set retains the original class distribution.

| Model | `caret` method | Key hyperparameters |
|-------|----------------|---------------------|
| Multinomial Logistic Regression | `multinom` | `decay` |
| Linear Discriminant Analysis | `lda` | `prior` |
| Support Vector Machine | `svmRadial` | `sigma`, `C` |
| K-Nearest Neighbors | `knn` | `k` |
| Naive Bayes | `naive_bayes` | `usekernel`, `laplace`, `adjust` |

### Evaluation Metrics

- Accuracy, Kappa
- Per-class Precision, Recall, F1
- Macro-F1
- ROC-AUC and PR-AUC (one-vs-rest)

## Results

Performance on the hold-out test set (original class distribution):

| Model | Accuracy | Kappa | Macro-F1 |
|-------|----------|-------|----------|
| **SVM (RBF, tuned)** | **0.9975** | **0.9607** | **0.9731** |
| Multinomial Logistic Regression | 0.9928 | 0.8994 | ~0.940 |
| Naive Bayes (tuned) | 0.9818 | 0.7786 | 0.8698 |
| KNN (tuned) | 0.9380 | 0.4736 | 0.681 |
| LDA | 0.9022 | 0.3692 | 0.6975 |

**Summary**

- **Best overall:** Tuned RBF-SVM — strongest balance across all classes, especially Fair recall
- **Interpretable baseline:** Multinomial Logistic Regression
- **Lightweight alternative:** Naive Bayes
- **Shared challenge:** The minority *Fair* class remains difficult to classify with high precision

## Limitations

1. **Severe class imbalance** — Good accounts for ~96.7% of records. Accuracy alone can be misleading; use Macro-F1 and PR-AUC alongside Accuracy.
2. **Weather granularity** — Weather is joined by date only. All sites on the same day share one weather record; site-level microclimate is not captured.
3. **SVM pipeline** — The SVM section uses a separate data-loading path (`set.seed(42)`) from the main workflow (`set.seed(5003)`).
4. **No temporal validation** — The current 80/20 split is random. Time-based or site-grouped validation would better assess deployment performance.
